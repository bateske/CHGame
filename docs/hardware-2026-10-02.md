# Hardware session, 2026-10-02: every game's debug build on the board

One CHGame (menu bootloader, BOOT_VERSION 2) on USB. For each game, a debug
build was uploaded and two of its scripts were driven over the debug
protocol by `tools/device.py run`: `gameplay.txt` (the README reel) and
`perf.txt`. The same scripts were then run in the simulator and the clips
compared frame by frame. A person watched the board; nobody played the
games by hand except where noted.

## What this does and does not cover

- **Covered:** the debug build starts, takes the script's presses and debug
  commands, draws what the simulator draws, and reports its render time and
  stack depth (`P`).
- **Not covered:** the release builds (only CHSnakes was played, briefly, and
  CHFour was uploaded and started), the sound by ear, saving across a power
  cycle, the pace of a free-running game, and the SD games against the
  files on a real card. A debug build of most games is the lean one
  (`<PFX>_LEAN`: no saving, some screens left out).
- **When:** before the fixes of the same day were in. The runs used the
  core as installed (0.2.4), then the repository's core with the USB fix
  below. The stack-paint bug in `dbg::begin()` (fixed afterwards, see
  [status.md](status.md)) was still there; it stopped CHSnakes at its first
  frame and is why that game has no row of numbers here.

## What stopped, and why

- **`auto` in CHBackgammon and CHWords.** The debug command has the CPU
  choose a move inside the debug hook. On the board that takes longer than
  the driver's 30 s reply timeout. The game is alive afterwards (a
  screenshot was taken). The scripts are simulator scripts; CHBackgammon
  has `device_think.txt` for the board.
- **A command the lean build leaves out** (CHCheckers `H`, CHChess `R`,
  CHCraps `Z`, CHMahjong `O`) or one that exists only in the simulator
  (CHSolitaire's `say X`, every `perf.txt`'s `cal`). `cal` is now skipped on
  the board; the others want a device script each, or a full debug build
  where it fits.

## Bugs found

1. **The USB serial port could go mute** (core,
   `cores/arduino/ch32/usb/wch_usbcdc_cdc.c`). `CDC_flush()` armed the
   packet and then set the busy flag; an interrupt between the two (a
   display flush, the sound timer) let the host take the packet first, the
   flag was then set with nothing left to clear it, and every later write
   was dropped. Seen as scripts that stopped with "no reply from device",
   at a different step each run: 12 of the first 34 runs. CHCrossword's
   `gameplay` stopped three times out of three before the fix and ran to
   the end every time after it; of the 12, only the two `auto` stops above
   remained. It affects any sketch that prints while it draws; release
   games have no serial path.
2. **A debug build stopped at its first frame** (library, `dbg::begin()`),
   found in CHSnakes: see [status.md](status.md), Known issues.
3. **The script driver could lock the serial port** (`tools/serialcap.py`).
   A write to a board that is not reading blocked for ever, and Windows
   does not let go of the port until the board is unplugged. Writes now give
   up after 2 s. Closing a port with a write still pending can block all
   the same, so a crashed sketch may still need the board switched off and
   on.
4. **`chgame-upload probe` calls a board it cannot open "application".** A
   busy port and a silent sketch print the same line.

## The bootloader from Arduino

*Burn Bootloader* over USB (the programmer **CHGame USB**,
`chgame-upload burn -method usb`) was run through `arduino-cli
burn-bootloader` for every change between the three bootloaders the package
offers: SD menu to classic 0.2.4, classic to no-menu, no-menu to classic,
classic to SD menu. Then *Upload Using Programmer* (bootloader and sketch)
and a normal upload. All worked. The factory ISP path was run only as far
as its "no device in ISP mode" message.

A release build compiled by plain `arduino-cli compile`, with no `--library`
flags, against this repository's board package gave the same bytes as
`tools/device.py build` (CHFour).
