# Hardware results, 2026-10-03: menu v2

Menu v2 (BOOT_VERSION 3: folders, the card's picture and order, the launch
game, ERROR n) was installed on the same CHGame as on 2026-10-01 by
self-update over USB, in three builds one after another. The owner watched
the screen, pressed the buttons and switched the power; a Claude Code session
on the PC ran the commands.

**Outcome.** Everything the owner checked works. The owner then asked for
three changes (a solid rainbow instead of a gradient, a White style, folders
placed by the tools), which were made, passed the PC suite, and were tried
on the board the same day ("Round 2"). The images in `release/` are the ones
that ran: `chgame_sdboot.bin` and `chgame_sdboot_white.bin` are byte for byte
the builds installed in round 2.

Not tried on the board, still to do: the launch game at power-on (and START
held to skip it), the ERROR n boxes, the INSTALLED PROGRAM row, a picture of
the owner's own (`chgame background ... --card`), and `-verify` on v3. All are
covered by the PC suite (`test/native`: `t_cart_launch*`, `t_bad_packages`,
`t_upload_at_menu`, the preview check).

## Setup

| | |
|---|---|
| Repository | branch `claude/chgame-format` |
| PC | Windows 11, Python 3.13, arduino-cli 1.4.1, the board package `0.3.0-local` |
| Board before | the first menu bootloader (BOOT_VERSION 2), a valid sketch, COM8; chip UID `CDAB88D860BEB542` |
| Card | 16 GB microSD, FAT32 |

## Round 1: menu v2 as first built (gradient rainbow, 224 a folder)

| Step | Result |
|---|---|
| `chgame uploader touch`, `info` | bootloader v2, application valid |
| `chgame --sketch CHSDtoUSB upload` (its own FQBN, `opt=osstd`) | uploaded through the v2 bootloader, the card mounted as G: |
| The card before | `GAMES/` held only the 2026-10-01 casino CHG files (the old names); other files at the root (`BENCH.DAT`, `CRITTERS.DAT`) were left alone |
| `chgame cart deploy out/CHGame-Casino.chgame --card G:/ --clean` | 34 files; read back, all byte for byte the prepared card; ejected |
| `chgame uploader selfupdate build/release/chgame_boot.bin --yes` | promoted, "bootloader v3 is running on COM8"; `info`: v3, no application (the update erases it) |
| The look, scrolling, APPS (A in, B back to its row), installing FOUR IN A ROW and the 3 s START exit, a power cycle, SD CARD READER from inside APPS | **"this works great"** (the owner) |
